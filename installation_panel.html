Панель инсталляций

Административная панель для управления установкой оборудования

Обзор

Продукт: внутренний инструмент для отслеживания процесса монтажа умных камер и устройств на транспортные средства. Менеджеры контролируют статус установок в разрезе компаний-клиентов, типов транспорта и команд установщиков.

Задача

Данные по установкам были раскиданы по разным местам: разделы жили каждый сам по себе. Нужно было собрать всё в единый портал с тремя связанными модулями:

  • группы установок;
  • реестр установщиков;
  • привязанный транспорт.

Ход работы
[1]

Перед ТЗ поресёрчил паттерны админ-панелей: увидел, что в них по максимуму переиспользуют одни и те же сущности, а консистентность стоит на первом месте, потому что админка обязана быть однородной.

[2]

Работал в связке с дизайн-лидом, вели проект вместе.

[3]

Подобрал формат под тип данных, а не один шаблон на всё: таблица для групп установок, чтобы проще агрегировать и фильтровать; карточки для транспорта, чтобы модель считывалась по картинке, а не по тексту.

[4]

Консистентность в деле: профиль установщика и форма его создания используют одну и ту же структуру, один паттерн для чтения и записи.

Панель инсталляций
6 экранов: сквозная навигация
[1]

Группы установок. Сводный список: клиент, тип транспорта, статус, количество единиц, с фильтром по статусу и компании. Выбрал таблицу: с ней проще агрегировать и фильтровать, а строк может быть сколько угодно, ничего не потеряется.

[2]

Детали установки. Из списка сразу в конкретную инсталляцию: установщики, статус по каждому ТС, дата, отдел-заказчик. Собрал это таймлайном, вытянутым по вертикали: паттерн понятный, этапы идут один за другим, можно проскроллить и увидеть, что уже сделано.

[3]

Собрал все установки конкретного отдела в одном месте, чтобы не листать их по одной.

[4]

Собрал реестр установщиков с поиском по имени, статусу, числу активных заданий и компании, чтобы находить нужного монтажника за секунды. Клик по строке ведёт в профиль.

[5]

Собрал в профиле установщика всю историю и текущую нагрузку сразу (назначенные ТС, группы, контакты), чтобы не запрашивать это по частям.

[5.1]

Сделал форму создания идентичной по структуре профилю: один и тот же паттерн для чтения и записи, ничего не нужно запоминать заново.

[6]

Транспортные средства. Список ТС: тип, номер, статус установки, назначенный установщик. Здесь выбрал карточки, а не таблицу: важно узнать модель по картинке, а не читать текст.
